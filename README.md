# EduFinance Hub – About and Calendar Pages

## Project overview
This repository contains the **About** and **Calendar** components of the EduFinance Hub Term 3 project. The application was developed in Java using NetBeans/Maven and connects to an Oracle database through JDBC.

The project uses Java's built-in HTTP server, so Tomcat, Payara, JSP and Servlets are not required for these pages.

## Database configuration
For security, database credentials are **not stored in the source code**. Before running the project, configure these environment variables:

```text
EDUFINANCE_DB_USER=<your Oracle username>
EDUFINANCE_DB_PASSWORD=<your Oracle password>
```

Optional, if your Oracle connection URL differs from the default:

```text
EDUFINANCE_DB_URL=jdbc:oracle:thin:@localhost:1521/FREEPDB1
```

The application expects the existing `CALENDAR_EVENTS` table used by the project.

> Never commit passwords, `.env` files, or other private credentials to GitHub.

## Running the project in NetBeans
1. Clone or download this repository.
2. Open **Apache NetBeans IDE**.
3. Select **File > Open Project** and choose the project folder.
4. Allow Maven to download the required dependencies.
5. Configure the database environment variables on the computer running the project.
6. Make sure the Oracle database is running and the `CALENDAR_EVENTS` table is available.
7. Run `TestDatabase.java` if you want to verify the database connection first.
8. Right-click the project and select **Run**.
9. Open the following pages in a browser:
   - Calendar: `http://localhost:8080/calendar`
   - About: `http://localhost:8080/about`

## Database and application flow
The user interacts with the Calendar interface served by `Main.java`. Calendar requests are passed to `CalendarDAO`, which uses `DBConnection` to communicate with Oracle through JDBC. Database results are represented by `CalendarEvent` objects and returned to the interface for display. Create, update and delete operations are written to the database and reflected by the application.

## Error handling and validation
The project includes validation and feedback for calendar operations. Database connection failures are reported rather than silently ignored, and destructive actions such as deletion require confirmation.
